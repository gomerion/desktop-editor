# План разработки десктопного приложения "STO-Editor" (Java)

## 1. Обзор проекта
Разработка WYSIWYG-подобного редактора с текстовой разметкой (DSL) на базе JavaFX. 
Приложение предназначено для автоматической верстки учебных отчетов в строгом соответствии со стандартом **СТО 02068410-004-2018** (Самарский университет).

### Ключевая концепция:
- **Слева:** Текстовый редактор с кастомным Markdown-подобным синтаксисом (STO-Markup).
- **Справа:** Область реального времени (Live Preview) с предпросмотром итогового PDF.
- **Движок:** Автоматическая нумерация, форматирование, сборка титульных листов, таблиц, рисунков и списков литературы по СТО.

## 2. Спецификация собственного языка разметки (STO-Markup)

Синтаксис проектируется так, чтобы уйти от сложностей LaTeX, но при этом иметь явную семантику под требования ГОСТ/СТО.

### 2.1. Метаданные (Front Matter)
Используются в начале файла для автоматической генерации титульного листа и колонтитулов.

```sto
---
document_type: vkr_bachelor # vkr_master, vkr_specialist, report, lab
university: "САМАРСКИЙ НАЦИОНАЛЬНЫЙ ИССЛЕДОВАТЕЛЬСКИЙ УНИВЕРСИТЕТ ИМЕНИ АКАДЕМИКА С. П. КОРОЛЕВА"
faculty: "Институт информатики и кибернетики"
department: "Программные системы"
topic: "Разработка редактора технической документации"
student: "И. И. Иванов"
group: "6401-090301D"
supervisor: "доцент, к.т.н. П. П. Петров"
year: 2026
---
```

### 2.2. Структурные элементы
Структурные элементы отчета оформляются специальным синтаксисом без нумерации, печатаются прописными буквами по центру.

```sto
!! РЕФЕРАТ
!! СОДЕРЖАНИЕ
!! ВВЕДЕНИЕ
!! ЗАКЛЮЧЕНИЕ
!! СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ
```

### 2.3. Заголовки и разделы
Автоматически нумеруются с соблюдением иерархии (1, 1.1, 1.1.1) и требований к абзацному отступу.

```sto
# Заголовок раздела 1
## Заголовок подраздела 1.1
### Пункт 1.1.1
```

### 2.4. Списки (Перечисления)
Поддержка правил СТО: дефисы, строчные буквы с круглой скобкой, арабские цифры.

```sto
* Элемент списка с дефисом
* Второй элемент

a) Элемент с буквенной нумерацией
б) Второй элемент

1) Цифровой список
2) Второй элемент
```

### 2.5. Рисунки, Таблицы и Формулы

* **Рисунки** (выравнивание по центру, подпись под рисунком):
```sto
@fig(src="architecture.png", caption="Архитектура приложения", id="arch_scheme")
```

* **Таблицы** (выравнивание подписи слева, над таблицей, автоматическое дублирование головки при переносе):
```sto
@table(caption="Результаты экспериментов", id="exp_res")
| Серия опытов | Давление, Н/м² | Тяга, Н |
| ------------ | -------------- | ------- |
| 1-ая         | 77             | 160     |
| 2-ая         | 82             | 172     |
@endtable
```

* **Формулы** (выравнивание по центру, номер справа в скобках, описание символов с "где"):
```sto
@math(id="density")
\rho = \frac{m}{V}
@where
m - масса образца, кг;
V - объем образца, м³.
@endmath
```

* **Перекрестные ссылки в тексте**:
```sto
Как показано на @ref(fig:arch_scheme) и в @ref(tab:exp_res), расчет проводился по формуле @ref(math:density).
```

## 3. Архитектура приложения

Приложение строится по модульной схеме с четким разделением ответственности.

```
[ UI Layer (JavaFX) ]
   ├── RichTextFX (Editor)
   └── WebView / PDF.js (Preview)
         │
         ▼ (Debounce 300ms)
[ Parser Engine (ANTLR4 / Custom AST) ]
   └── STO-Markup Parser -> AST Document Tree
         │
         ▼
[ Compiler Engine ]
   ├── AST -> STO-Compliant HTML Generator
   └── Dynamic CSS Engine (СТО Typography & Page Layout)
         │
         ▼
[ PDF Renderer (OpenHTMLtoPDF / PDFBox) ]
   └── Output PDF File / Stream
```

## 4. Этапы реализации

### Этап 1: Проектирование парсера языка STO-Markup
1. **Разработка грамматики (ANTLR4 или ANTLR/Lexer):**
   - Определение лексем (заголовки, директивы `@fig`, `@table`, `@math`, списки).
   - Построение абстрактного синтаксического дерева (AST).
2. **Создание внутреннего представления документа:**
   - Модели `DocumentNode`, `SectionNode`, `FigureNode`, `TableNode`, `FormulaNode`, `ReferenceNode`.
3. **Реализация менеджера ссылок и счетчиков:**
   - Автоматический подсчет рисунков, таблиц, формул и их валидация по разделам (например, `Рисунок 1.2` или сквозная нумерация `Рисунок 1`).

### Этап 2: Генератор HTML/CSS по стандарту СТО
1. **Верстка базoвого CSS3 (Paged Media):**
   - Настройка полей страницы: слева 30 мм, справа 15 мм, сверху/снизу 20 мм.
   - Шрифт Times New Roman 13pt / 14pt, полуторный межстрочный интервал, красная строка 1.25 см.
   - Стили для нумерации страниц внизу по центру.
2. **HTML-транслятор:**
   - Преобразование узлов AST в HTML5 со строгой семантикой CSS-классов (например, `<h1 class="structural">`, `<div class="sto-figure">`).
3. **Генерация титульного листа и служебных страниц:**
   - Шаблонизатор (FreeMarker или StringTemplate) для титульного листа по Приложению А.

### Этап 3: Модуль генерации PDF
1. **Интеграция OpenHTMLtoPDF (PDFBox):**
   - Преобразование сгенерированного HTML + CSS в векторный PDF.
   - Подключение MathML/SVG генератора для отображения математических формул LaTeX (`@math`).
2. **Оптимизация производительности:**
   - Использование `FastMode` в OpenHTMLtoPDF.
   - Кеширование тяжелых ресурсов (шрифты, изображения).

### Этап 4: Разработка UI (JavaFX)
1. **Интерфейс:**
   - SplitPane: Слева — текстовый редактор, Справа — область предпросмотра.
2. **Редактор кода (RichTextFX):**
   - Подсветка синтаксиса STO-Markup.
   - Автодополнение директив (`@fig`, `@table`, `@math`).
   - Нумерация строк.
3. **Область предпросмотра (Live Preview):**
   - Встраивание `WebView` с библиотека Mozilla `PDF.js` или рендеринг страниц PDF в `ImageView`.
   - Фоновый поток (`Task` / `CompletableFuture`) для компиляции.
   - Реализация **Debounce** (задержка обновления 300-500 мс при наборе текста).
   - Синхронный скролл (при клике на раздел в коде — переход к соответствующей странице PDF).

## 5. Технологический стек

- **Язык:** Java 21+
- **GUI Framework:** JavaFX 21+
- **Code Editor Component:** RichTextFX
- **ПарсингDSL:** ANTLR 4
- **Конвертация в PDF:** OpenHTMLtoPDF (на базе PDFBox 2)
- **Рендеринг формул:** JLaTeXMath (преобразование LaTeX в SVG/PNG)
- **Сборка:** Apache Maven / Gradle

## 6. Риски и их минимизация

1. **Задержки при рендеринге PDF в реальном времени:**
   * *Решение:* Компилировать только измененные страницы или использовать задержку (Debounce) при вводе.
2. **Несоответствие верстки правилам СТО:**
   * *Решение:* Жестко зафиксировать правила в базовых CSS-стилях Paged Media (запретить пользователю прямую вставку произвольных инлайн-стилей).
3. **Сложность переноса таблиц на несколько страниц:**
   * *Решение:* Использование CSS-свойств `thead { display: table-header-group; }` и специфичных директив OpenHTMLtoPDF (`page-break-inside: avoid`).
